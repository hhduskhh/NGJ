# 026-房间障碍与装饰扩展报告

## 结论摘要

当前房间“空”的主要原因不是道具数量少，而是**每个锚点只放一个掩体、墙面只装饰顶边、没有地板贴花/悬挂装饰/大件组合**。在现有 18×14 房间中，1×1 房通常只有 1–2 个实心物，2×2 房也只有 4 个左右，视觉上必然显得平。

本报告建议：

1. 房间格改为 **36×36**，5×5 地图变为 **180×180**，内部约 34×34；门宽 4→6。
2. 相机参考分辨率改为 **640×360**（视野约 40×22.5 格），大房间仍会跨屏。
3. 地图渲染改为分块或 Tilemap，避免 32,400 个独立格子对象拖慢生成和帧率。
4. 把“锚点随机放一个道具”改为**房间布局预设库**：每房型 3–5 套，按主题替换道具，按旋转复用。
5. 增加三层装饰：地板贴花、墙面装饰、悬挂/顶饰；实心物只占画面的一部分，密度主要靠非碰撞装饰。
6. 先复用现有 16 种道具做 P0 布局，再补 **P1 约 15 件新素材**；完整方案约 40–60 件新素材。

本报告只做设计与素材规划，**没有修改代码**。

## P0 逻辑实现状态（2026-11-14）

报告确认后已先完成不依赖新美术的逻辑部分：

- 房间格 **36×36**，地图 **180×180**，门宽 **6**，相机 **640×360**。
- 地面改用 Tilemap；墙体保留逐格 Y 排序；视野纹理 180×180、shader 512。
- 新增 `RoomLayouts.cs`：donut、柱厅、货箱 S 路、断角、长厅、庭院、L 转角、Boss 四角柱、起始集市。
- 新增地板贴花、墙面装饰、非碰撞杂物；Boss 房不放普通地板杂物。
- 敌人 **6 只/房间格**，单房 6–28；第一层 seed 713 约 139 只普通怪。
- 第一层中间房实测 **9–22 个实心物，覆盖率 6.7–10.2%**；P0 用现有 32×32 道具，尚未达到本报告 10–18% 的目标。
- P1 仍需按下方“美术素材清单”补大件、贴花和墙饰，才能把覆盖率和视觉体量提升到目标。


## 一、现状审计

### 1.1 当前生成规则

- 房间格 18×14，5×5 地图 90×70。
- 中间房实心物来自每层 5–6 种道具池，`DungeonMap.BuildObstacleCandidates` 按房型固定锚点：
  - 1×1：2 个锚点；
  - 1×2：2 个锚点；
  - 1×3：4 个锚点；
  - 2×2：中心四周 4 个锚点；
  - L：4 个角锚点。
- 每个锚点随机挑一种道具，`TryBlockObstacle` 要求周围 1 格地板、离门 2 格；1×1 房经常只能成功 1–2 个。
- 墙面装饰 `RenderWallDressing` 只放在每格顶墙的 `x0+3`、`x0+12` 两个位置。
- 没有地板贴花、悬挂物、顶饰、低矮杂物、成组家具或房间内部子结构。

相关位置：

- `Assets/Echoes/Scripts/World/DungeonMap.cs`：`BuildObstacleCandidates`、`TryBlockObstacle`、`RenderWallDressing`。
- `Assets/Echoes/Scripts/World/GameArt.cs`：每层 16 种 `props` 切片。
- `Docs/025-房间生成与三层地牢.md`：已记录“未新增房间专属素材”的限制。

### 1.2 直接结果

| 房型 | 当前内部面积 | 当前实心物数量 | 观感 |
| --- | ---: | ---: | --- |
| 1×1 | 16×12 | 1–2 | 像空房间 + 两个箱子 |
| 1×2 | 34×12 | 2–7 | 两端空，中间偶尔一两个 |
| 1×3 | 16×38 | 4–7 | 长条空廊 |
| 2×2 | 34×26 | 4–7 | 中心一圈，四角空 |
| L | 34×26（缺角） | 4–7 | 两臂缺少层次 |

### 1.3 现有引擎约束

- `walkable=false` 同时承担“碰撞阻挡”和“视线阻挡”；如果要“矮掩体挡移动但不挡视线”，需要新增独立的 `sightBlocking` 掩码。
- 敌人寻路是格子 BFS，必须保证门与房间内主通路连通；不能用 1 格窄缝做装饰。
- 玩家自动瞄准要求可见目标；房间中央不能放整面高墙，否则会变成“看不到人”的挫败感。
- 声波穿墙、视野被墙遮挡；障碍应制造“绕柱、卡视线、换角度”的机会，而不是把房间切成迷宫。

## 二、尺寸调整（按已确认方向）

| 项目 | 当前 | 建议 |
| --- | ---: | ---: |
| 房间格 | 18×14 | **36×36** |
| 内部尺寸 | 16×12 | **34×34**（1 格墙） |
| 地图 | 90×70 | **180×180** |
| 门宽 | 4 格 | **6 格** |
| 墙厚 | 2 格 | 2 格 |
| 相机参考 | 480×270 | **640×360** |
| 可见视野 | 约 30×17 格 | 约 40×22.5 格 |

### 2.1 连锁影响

- 地图格子数从 6,300 增至 **32,400**（约 5.1×），房间内部面积约 6×。
- 不能继续每个格子一个 `GameObject` 直接铺；建议：
  - 地面/墙体使用 Unity Tilemap 或分块合并网格；
  - 墙体碰撞使用 `CompositeCollider2D` 或按房间合并的 BoxCollider；
  - 道具/装饰仍用独立 SpriteRenderer，方便遮挡排序和交互。
- 可见性纹理改为 180×180；`DungeonDarkness.shader` 的 DDA 上限从 256 提到 **512**。
- 门宽 6 格，门洞两侧门柱位置、出生点离门距离、掩体离门距离都要重新标定。
- 相机 640×360 下，36×36 房间仍会跨屏；这是可接受的探索感，但 Boss 房/大型战斗房应保持中央 16×16 以上无障碍区域。

### 2.2 密度预算（建议）

| 房型 | 内部面积 | 实心物数量 | 实心覆盖率 | 非碰撞装饰 | 墙面装饰 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1×1 | 34×34 | 8–14 | 10–18% | 25–45 | 6–10 |
| 1×2 | 70×34 | 12–20 | 10–18% | 40–70 | 12–18 |
| 1×3 | 34×106 | 16–26 | 10–18% | 55–90 | 18–26 |
| 2×2 | 70×70 | 20–32 | 10–18% | 60–100 | 20–30 |
| L | 70×106 外接 | 14–22 | 10–18% | 45–80 | 14–22 |

- 主通路净宽 **4 格**；门口 3 格内不放实心物。
- 每房至少 2 条从门到门/到中心的路线；不能出现死胡同式窄缝。
- 中央区域保留“可读的开放空间”，不要把 1×1 房塞成迷宫。
- 实心覆盖率按房间内部面积计算，不含墙体。

### 2.3 敌人密度

36×36 是当前面积的约 5.1×，如果继续 2 只/格，全层会变成约 230 只，且寻路压力过大。建议：

- 第一版 **6 只/格**，单房下限 6、上限 28；全层约 **120–150 只**。
- 试玩后再决定是否提高到 8 只/格（约 160–190 只）。
- 敌人 `repath` 间隔分帧/随机化；必要时改为流场或房间级共享路径。
- 起始房 0 普通怪，Boss 房只放 Boss。

## 三、参考设计

### 3.1 Hypixel Skyblock Catacombs

- 房间规格包含 1×1、1×2、1×3、1×4、2×2、L；多格房是整块大房间。
- 典型 2×2 的 Cathedral 使用“中央 crossing + 四条 aisle + 外围 arc”的内部结构，而不是在空房间里随便摆几个方块。
- 可借鉴：多格房要有**内部子结构**（中央岛、十字通道、环廊、角室），让大房间有节奏。
- 不借鉴：Blood/Fairy/Puzzle/Trap 等特殊房和钥匙锁门，本轮不做。

### 3.2 Hades

- 房间是手工预制件，按生物群系组成房间池；灰盒阶段明确区分“全掩体/半掩体”、柱子、陷阱、出口。
- 经验：柱子能挡视线和弹道，但**柱子太多会挡玩家视野**；陷阱是补充，不应成为房间主角。
- 可借鉴：每房型预置 3–5 套固定布局，随机只选布局与主题道具，不随机到无法读图。
- 可借鉴：中央 choke point + 两侧开放区，让玩家有绕柱和换角度的空间。

### 3.3 Enter the Gungeon

- 先设计“房间流程图”，再在规则内填充房间；房间有明确职责（战斗、商店、Boss、连接）。
- 房间内部用柱子、坑、桌子、可破坏物形成战术几何，桌子是可翻起的临时掩体。
- 可借鉴：每层有“战斗房/休息房/商店/Boss”节奏；房间内部以 2–4 个掩体岛为单位，而不是均匀撒点。
- 不借鉴：坑、可破坏物、翻桌等新机制，除非后续单独实现。

### 3.4 The Binding of Isaac

- 房间是单屏格子竞技场；岩石/坑/尖刺与敌人组合形成 choke point、安全区、门口伏击。
- 关键不是障碍数量，而是**障碍与敌人、门口、奖励位置的组合**。
- 可借鉴：入口正对区域不要立即被高墙封死；用斜向/错位掩体制造“进入房间后先读图”的 1–2 秒。
- 避免：1 格窄道、障碍堵门、障碍把玩家逼进没有闪避空间的角落。

### 3.5 战斗空间设计原则

- 高掩体完全遮挡信息，低掩体让双方能看到上半身；两者混合才有决策。
- 掩体间距、密度、大小决定节奏：密度高 → 慢、谨慎；密度低 → 流畅、暴露。
- 视线比空间大小更重要；不要给玩家一个“完全安全、能打全场”的角落。
- 房间形状控制节奏：中央岛/环形（donut）迫使绕行；直角拐角制造紧张；十字/环廊提供多方向。
- 装饰必须服务于可读性：不要用高对比杂物遮住敌人、弹幕、门和地面危险提示。

### 3.6 本项目应避免

- 全部房间同一种“四角箱子 + 中心空”的模板。
- 实心物贴墙摆一圈，中间全空。
- 高墙把 1×1 房切成 1 格宽通道。
- 只有实心掩体、没有地板/墙面/顶饰，导致“空”和“脏”同时出现。
- 每层都用同样的箱子；主题只换颜色，不换轮廓。

## 四、布局设计规则

### 4.1 三层空间

每个房间按“外环 / 中环 / 中心”三层考虑：

- **外环**：门、门柱、墙边装饰、靠墙家具；保证门口 3 格净空。
- **中环**：主战斗区；放 2–4 个掩体岛（柱、箱堆、机器、碎石），岛之间留 4 格以上通道。
- **中心**：1×1 房可放中央机岛/祭坛/钟架；Boss 房中心必须留空；起始房中心不放实心物。

### 4.2 掩体类型

本轮引擎里 `walkable=false` 同时挡移动和视线，因此：

- 实心掩体 = 全掩体：柱子、机器、箱堆、碎石堆、断墙。
- 非碰撞装饰 = 地板裂缝、油迹、纸片、管线、挂饰、低矮杂物；只做视觉叙事。
- 若后续要“矮掩体挡移动但不挡视线”，需要新增独立 `sightBlocking` 掩码；建议放到 P3，不在本轮混入。

### 4.3 主题轮廓

| 主题 | 应多用的轮廓 | 应避免 |
| --- | --- | --- |
| 静钟街区 | 圆钟、拱、长椅、断柱、木箱、铜管、碎石 | 大面积机械、晶体 |
| 锈鸣工坊 | 方壳、锅炉、管道、齿轮、传送带、钢箱 | 石制拱门、纯装饰晶体 |
| 原音圣所 | 竖向菱晶、音叉、管风琴、白瓷壳、金线基座 | 锈铁、木箱堆、油污 |

同一房型在三层应有不同的“主轮廓”，不能只换色。

## 六、美术素材清单

### 6.1 现有可复用

每层已有 16 种 `props`：箱、灯、门柱、维修站、主题物、祭坛、柱、武器架、直管、弯管、长椅、音叉、晶体、面板、零件、导音槽。

P0 阶段不新增美术，用“同类成组 + 不同旋转 + 地板贴花（可由现有 tile 变体/几何色块临时替代）”先做出更密的布局；但 32×32 的单件在 36×36 房间里会偏小，因此 P1 需要大件。

### 6.4 规格与导入

- 16 PPU；Point；无 mipmap；无压缩；Alpha 0/255（特殊光效除外）。
- 实心道具 pivot 底边中心；地板贴花中心；墙面装饰底边/中心按用途。
- 现有 `props.png` 是 8×2 的 32×32 固定格；64×64、96×32 等大件建议使用独立图集（如 `props_large.png`、`decals.png`），避免破坏现有切片。
- 碰撞脚底在代码/预设数据中配置，不烘焙进图；同一素材可在不同布局复用不同碰撞。
- 新素材通过 `ProductionArtImporter` 增加对应切片规则；`GameArt` 增加 kind 映射；保留来源/提示词与授权说明。

| 阶段 | 内容 | 新增素材 | 说明 |

## 七、实现方案

### 7.1 尺寸与渲染

1. `DungeonMap.CellWidth/CellHeight` 改为 36/36，地图 180×180。
2. 门洞宽 4→6；`CarveDoors`、`RenderDoorposts`、出生点/掩体离门距离同步。
3. 相机参考 640×360；`PrototypeBuilder` 的 `PixelPerfectCamera` 设置同步；HUD 仍用 1600×900 Canvas。
4. 地面/墙体改为 Tilemap 或分块网格；保留 `walkable`/`floor` 网格用于寻路、视野和生成校验。
5. 视野纹理 180×180；shader DDA 上限 512。

### 7.2 布局预设库

新增 `RoomLayoutPreset`（可由 C# 静态数据或 ScriptableObject 提供）：

```text
RoomLayoutPreset
  shape        1x1 / 1x2 / 1x3 / 2x2 / L
  themeMask    0..2
  roleMask     Middle / Boss / Start
  weight
  solids[]     kind, local tile x/y, footprint w/h
  decor[]      kind, local tile x/y, layer (floor/wall/overhead)
  wallDress[]  kind, local tile x/y
  spawnHints   local tile positions / zones
```

- 每个房型至少 3 套中间房布局，每套可用主题道具替换。
- 预设按房间旋转 0/90/180/270 复用；L 形按旋转后的多边形裁剪。
- 生成时先选布局，再选主题道具变体；不再按固定锚点随机撒点。
- 布局校验：
  - 4 格主通路；门内 3 格净空；
  - 实心覆盖率 10–18%；
  - 门到门/门到中心 BFS 连通；
  - 至少 2 条路线；
  - 出生点数量 ≥ 6/格；
  - 没有不可见碰撞、没有 1 格窄缝。

### 7.3 装饰层

- **地板层**：裂缝、油迹、苔藓、纸片、硬币、灰尘；排序在地面之上、角色之下。
- **墙面层**：灯、旗、管线、通风口、壁龛；只放在墙格。
- **悬挂/顶饰**：链、吊钟、电缆、吊灯；排序在角色上方，无碰撞。
- **非碰撞杂物**：小堆零件、骨头、陶片、书页；不进入 `walkable`。

装饰密度按表 2.2 执行；同一房间避免 3 个以上同款装饰紧挨，防止“复制粘贴感”。

### 7.4 敌人与性能

- 第一版 6 只/格，单房 6–28；全层约 120–150。
- 敌人寻路分帧；必要时使用房间级流场/共享路径。
- 180×180 地图、约 150 敌人、32k 格子：需要在开发机实测 60 FPS 和生成 <2 秒；不达标就先减敌人/装饰或继续优化渲染。

### 7.5 测试

- EditMode：300 seeds 布局规则；预设覆盖率/连通/密度；旋转一致性。
- PlayMode：实际场景 180×180 生成、门/Boss/商店/三层、出生点、寻路、视野/子弹、截图。
- 新增布局截图：每种房型 × 主题 × 2 套布局。

## 八、建议验收标准

- **尺寸**：房间格 36×36；地图 180×180；内部 34×34；门宽 6；相机 640×360。
- **布局**：每房型至少 3 套预设；不同主题主轮廓不同；1×1 房实心物 8–14 个、覆盖率 10–18%；非碰撞装饰 25–45 个。
- **通路**：主通路 ≥4 格；门内 3 格净空；门到门至少 2 条路线；无死胡同窄缝；所有房间可达。
- **可读性**：中央不出现整面高墙；Boss 房中央 16×16 净空；装饰不遮敌人/弹幕/门。
- **敌人**：6 只/格左右，单房 6–28；合法出生点；跨门追击正常。
- **性能**：生成 <2 秒；开发机 1600×900 下稳定 60 FPS。
- **美术**：P0 可复用现有素材；P1 新增素材按规格导入、有碰撞脚底、有截图验收。
- **文档**：更新 `Docs/025`、本报告和 README；不生成 EXE（除非另行要求）。

## 九、建议实施顺序

1. **尺寸先行**：36×36 方格、180×180、门宽 6、相机 640×360、分块渲染。
2. **P0 布局库**：每房型 3 套，用现有道具；先解决“空”和“千篇一律”。
3. **密度与通路测试**：把实心覆盖率、主通路、出生点做成自动校验。
4. **P1 美术**：每主题 5 件大件 + 6 种贴花/墙饰；导入后再替换布局中的占位组合。
5. **P2 墙面/悬挂/大件补全**；最后再考虑矮掩体和可破坏物。
