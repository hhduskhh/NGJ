# 051-房间动线重制

## 功能

按 `Docs/新建 PPTX 演示文稿.pptx` 重做各房型内部动线：

- 蓝色外框：房间边界。
- 灰色：室内隔墙，参与碰撞、寻路与视线遮挡。
- 红色：陷阱锚点，落地后生成地刺或炸弹。
- 白色开口：墙体上的通行缺口。

出生房保持开阔；Boss 房改为内外两圈陷阱环；其余房型按出现顺序轮换图纸变体，每种房型的第一次出现必定是带陷阱的变体。

## 规则与实现

- 变体分配：`Room.LayoutVariant` 按同房型出现顺序轮换；每种房型第一次出现的房间使用带陷阱的变体，保证每层至少有一处陷阱教学。
- 墙体生成：`RoomInterior.Partitions` 输出世界坐标的计划墙体；`DungeonMap.ApplyRoomWalls` 在门洞周围留出 2 格清空带，应用后做房间连通性校验，不连通则回退对应墙体；实际墙体记录在 `Room.Walls`，供测试、装饰与示意图使用。
- 斜墙：使用 1 格宽的阶梯墙（Bresenham 栅格化），4 向寻路不可穿透，斜向视觉仍保持挡墙轮廓。
- 陷阱：`RoomInterior.TrapAnchors` 输出图纸红点；`PlaceTraps` 在锚点附近寻找可走且未被占用的格子，必要时扩大搜索半径，保证每个锚点都有落点。地刺与炸弹按锚点顺序交替。
- 禁刷区：`RoomInterior.NoSpawnZones` 标记双菱形密室内部；`DungeonMap.SpawnCells` 会排除禁刷区内的格子。
- 刷新点：新增 `spawnCellStride`，默认从固定 3 格采样改为 2 格，候选刷新点约翻倍；`enemiesPerCell` 6→7，`maxEnemiesPerRoom` 28→32。
- 装饰：新增 `AddInteriorWallDecor`，按主题在室内隔墙上布置壁灯、墙管或壁龛架；每格地面贴花提升到第一层 16、第二层 16、第三层 20 个。墙体挤占家具空间时，`EnsureRoomCover` 以逐格扫描补充原生小家具，保证实心物数量与覆盖率下限。

## 验证

Unity 2022.3.62f3c1 PlayMode 批量回归 40 项全部通过，覆盖：

- `RoomTrapTests`：三层墙体碰撞、陷阱数量与图纸锚点一致、房间中心可达、禁刷区无刷新点、炸弹/地刺伤害。
- `FloorGenerationTests`：6 个种子 × 3 层连通性、生成耗时、实心数量与覆盖率、Boss 流程。生成耗时约 0.5 秒/层（早期逐墙做连通性校验时曾达到 11 秒，已改为每房间一次校验）。
- 房间美术与物理：`FirstFloorRoomArtTests`、`SecondFloorRoomArtTests`、`ThirdFloorRoomArtTests`、`RoomPropPhysicsTests`、`PropOcclusionTests`。
- 视野、战斗、寻路：`ObstacleVisibilityTests`、`RuntimeSmokeTests`、`RoomCombatTrialTests`、`EnemyRoleTests`、`VisibilityAndUpgradeTests`、`HearingAndVisionPulseTests`、`GameplayVisionCaptureTests`。

为适配新的 Boss 位置随机化，`FirstFloorRoomArtTests` 的兜底截图改为按缺失房型搜索种子；`PropOcclusionTests` 改为选择周围空地最多的立柱，避免取样区域全部被室内墙包围。

示意图导出：运行 `RoomSchematicExportTests.ExportCurrentFloorSchematics`，再执行

```
python 美术/房间示意图制作/render_room_schematics.py --json TestResults/room-schematics.json
```

生成包含隔墙、陷阱与禁刷区的 `Docs/Images/房间示意图-20261114/` 和 `Docs/035-当前房间示意图.md`。

## 已知边界

- 合并 `origin/main` 后，全量 PlayMode 回归曾报告 4 项失败：两层房间覆盖率统计已按主干的 `NavigationBounds` 口径修正；另有门洞寻路距离、敌对子弹撞墙和武器射程 3 项待复核。
- 图纸为示意图，斜墙按 1 格阶梯近似；开口宽度与同心环缺口按可玩性取整。
- 不同变体的陷阱数量按图纸差异较大，部分房型（单格 1/2、双格 1/2）本身不含红色陷阱。
- 覆盖率保底会在环形房走廊补充小型家具，实际密度仍建议在编辑器中试玩确认。
- 陷阱只伤害玩家，不伤害敌人；后续如需改为双方生效，应单独评估平衡。
