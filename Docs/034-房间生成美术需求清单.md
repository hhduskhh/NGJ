# 034-房间生成美术需求清单

> 本文第 3 节是 P1 唯一制作清单；033 只保留方向与布局说明。P1 按 **33 类资产**计数，方向变体另计文件数。第一批为共用 3 类、第一层 9 类、第一层 Boss 柱 1 类，共 13 类，包含独立纵向长椅后交付 14 张 PNG。接入记录见 `035-第一层房间美术与碰撞接入.md`。

## 0. 目的与边界

本清单只定义 **房间生成/地形预设所需的美术**，供美术制作与导入验收使用。

- 不包含：主角、普通怪、精英、Boss 动作帧，武器/被动图标，商店 UI，子弹/特效，角色 UI。
- 已有可复用：每层 4 张地面 + 4 张墙体（16×16）、16 件道具（32×32）、门柱、祭坛、墙灯、主题挂饰、面板等。
- 本轮目标：把 P0 中“32×32 道具放大 1.5–5 倍”替换为原生尺寸素材，让 36×36 房间在 640×360 相机下达到 **10–18% 实心覆盖率**，同时保留 4 格主通路和 3 格门净空。
- 当前 P0 实测：中间房实心物 9–22 个，覆盖率 **6.7–10.2%**；缺口主要来自没有大件、没有真正的贴花/墙饰。

相关实现与方案：

- `Docs/032-房间生成与三层地牢.md`：当前房间生成、尺寸、相机、测试结果。
- `Docs/033-房间障碍与装饰扩展报告.md`：参考布局、密度预算与完整 P2 清单。
- `Assets/Echoes/Scripts/World/RoomLayouts.cs`：P0 布局原型与当前占位道具。
- `Assets/Echoes/Scripts/World/GameArt.cs`、`Assets/Echoes/Editor/ProductionArtImporter.cs`：正式资源映射与导入规则。

## 1. 规格（所有 P1 素材必须遵守）

| 项目 | 要求 |
| --- | --- |
| 格式 | PNG，透明背景，无外框、无文字、无水印 |
| 像素密度 | 16 PPU；画布尺寸必须是 16 的倍数 |
| 过滤 | Point（Nearest），无 mipmap，无压缩，无抗锯齿 |
| Alpha | 实体道具 0 或 255；贴花允许半透明；特效除外 |
| 视角 | 与现有正式资源一致的俯视 3/4 像素风；墙体短正立面 |
| 调色 | 沿用 `build_assets.py` 的三层调色板；不新增高饱和主色 |
| 轮廓 | 1×1 缩放下仍能读出功能；底座与碰撞脚底清楚 |
| 文件命名 | `f{层}_{类型}_{名称}_{尺寸}.png`，例如 `f1_hero_bell_frame_128.png` |
| 来源 | `build_assets.py` 程序生成或 `image_gen`；保留生成提示词/来源说明 |

### 1.2 Pivot 与排序

| 类型 | Pivot | 排序 |
| --- | --- | --- |
| 实心道具 | 脚底基准 `(.5, .125)`；摊位为 `(.5, 0)`，底边对齐碰撞前沿 | 按脚底 Y 排序 |
| 地面贴花 | 中心 `(.5, .5)` | `-900`（地面 Tilemap 为 `-1000`） |
| 墙面装饰 | 底边中心或中心，按挂墙方式 | 按墙面 Y 排序 |
| 悬挂/顶饰 | 中心 | 角色上方，不参与碰撞 |

### 1.3 朝向与变体（执行要求）

- 固定相机、固定俯视 3/4 视角，光源来自左上。钟架、箱堆、碎石、断柱、Boss 柱和摊位保持竖直轴，不将整张立体图旋转 90°、180°，也不用镜像改变光源。
- 第一层长椅提供横向 `96×32` 与纵向 `32×96` 两张图；纵向是重新绘制的透视版本，碰撞分别为 `6×1`、`1×6`。宽房/方房用横向，纵向长房用纵向。
- 门楣是低矮石梁的纯顶视顶盖，门槛是纯顶视地面条，两者允许平面旋转 90°适配横/竖门洞。门柱保持直立。若后续改成完整立面拱门，必须另做侧门图，不能沿用该旋转规则。
- 第一批壁灯只挂在房间北边实体墙上，保持直立；南/东/西墙暂不放该图。后续需要四面墙饰时另增对应朝向，计入变体，不以旋转代替。
- 贴花是纯地面图，本批保持原向；没有碰撞，不影响拾取。票据和旧代币使用暗铜/灰纸色，与可拾取金币的亮金色区别。
- 源图与原生 PNG 使用同一命名；真正碰撞尺寸由代码配置。原生图片 `Scale=1`，不能为了补密度而放大。

## 2. 尺寸与碰撞标准

| 画布 | 占用格 | 建议碰撞脚底 | 用途 |
| ---: | ---: | ---: | --- |
| 128×128 | 8×8 | 6×6–8×8 | 1×1/2×2 中央 Hero |
| 96×64 | 6×4 | 5×3–6×4 | 中央次级/大型机器 |
| 64×64 | 4×4 | 3×3–4×4 | 中型掩体/角落集群 |
| 64×48 | 4×3 | 4×2–4×3 | 碎石/齿轮/封存匣 |
| 96×32 | 6×2 | 5×1–6×1 | 长椅/传送带/管道组 |
| 64×32 | 4×2 | 4×1 | 长椅/箱子 |
| 48×48 | 3×3 | 2×2–3×3 | 断柱/压力罐/晶簇 |
| 32×96 | 2×6 | 1×1–2×2 | 高柱/管风琴管 |
| 32×32 | 2×2 | 1×1–2×2 | 小掩体/箱/阀门 |
| 16×32 | 1×2 | 无 | 墙饰/小贴花 |
| 16×16 / 32×32 | 1×1 / 2×2 | 无 | 地板贴花 |

规则：

- 可视上部可以高于碰撞脚底；脚底必须落在碰撞 footprint 内。
- 不允许“看得见但能穿过去”的实心大件；也不允许完全不可见的碰撞。
- 大件放在房间中心/角落时，离墙 ≥1 格、离门 ≥3 格；主通路 ≥4 格。
- 当前 `RoomLayouts` 中 8×8/9×9/10×10 的缩放占位统一改为 **8×8 原生 Hero**；必要时通过布局把中心件从 10×10 调整为 8×8。

## 5. 导入与代码接入

建议 P1 使用**独立 PNG**，避免现有 8×2 `props.png` 固定切片规则被破坏：

```text
Assets/Echoes/Resources/Art/Room/
  Common/   door_lintel_6_96x32.png, door_threshold_6_96x16.png, start_stall_96x64.png
  Floor1/   f1_hero_bell_frame_128.png, ...
  Floor2/   ...
  Floor3/   ...
  Boss/     f1_boss_pillar_48x48.png, ...
  Decals/   floor1/..., floor2/..., floor3/...
```

接入步骤：

1. `ProductionArtImporter` 增加 `Art/Room/` 分支：Single Sprite，16 PPU，Point，无 mipmap/压缩；实心/墙饰 pivot 底边中心，贴花中心。
2. `GameArt` 增加按路径加载单张 Sprite 的入口，例如 `GameArt.RoomSprite("Floor1/f1_hero_bell_frame_128")`；缺失资源直接抛错，不静默回退。
3. `RoomLayouts` 把 P0 的缩放占位替换为 P1 原生 kind，`Scale=1`；同步更新 footprint。
4. 更新 `Docs/032` 截图与密度；P1 验收后覆盖率目标 ≥10%。
5. 不在本轮改 `props.png` 的 16 帧布局；旧 P0 保留为回退/缺图对照，但正式房间不得继续放大 4–5 倍。

## 6. 验收标准

- **文件**：P1 33 件全部存在，尺寸/Pivot/Alpha/16 PPU 正确。
- **读取**：`GameArt` 全部加载成功，无 missing/fallback；Unity 导入无切片错误。
- **布局**：中间房不再使用 128px 大件的 4–5 倍缩放；大件/中件/长件比例正确。
- **密度**：第一层中间房实心覆盖率 **10–18%**；主通路 ≥4 格；门内 3 格净空；无隐形碰撞。
- **表现**：3 层 × 5 房型 + 起始/Boss 截图通过人工检查；贴花低对比、不遮敌人/弹幕/门。
- **性能**：新增贴花/墙饰不造成明显帧率下降；生成时间仍 <2 秒/层。
- **文档**：更新 `Docs/032`、`Docs/033` 和 README；记录 P1 截图与覆盖率。

## 7. 建议制作顺序

1. **先做 6 件基础**：三张 Hero（128×128）、门楣/门槛、起始摊位；其中只有后三件为跨层共用。
2. **再做 3 张长件**（96×32）和 **6 张中型**（64×64/64×48），替换 1×2/1×3/2×2 的缩放占位。
3. **补 3 张高件/异形**（32×96、64×80、64×96）。
4. **最后做 9 张贴花 + 3 张墙饰 + 3 根 Boss 柱**。
5. 每完成一个主题就导入并生成该主题截图，不要等全部做完再一次性验收。

本次实际按第一层闭环交付 13 类：共用 3 + 第一层 9 + Boss 柱 1；后续第二、三层各 10 类。上面 6+9+3+15 合计 33 类，不含方向变体。

## 8. 不做的内容

- 不做新的角色、敌人、Boss 动作帧；已有正式资源。
- 不做商店武器/被动图标；已由商店素材流程交付。
- 不做 UI 面板/按钮；商店 UI 有独立清单。
- 不做可破坏物、陷阱、矮掩体视线分离；这些是后续机制，不是本轮美术。
