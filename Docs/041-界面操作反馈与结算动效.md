# 041 界面操作反馈与结算动效

按钮面板与文字一起下沉，命中区域固定。左键放开时执行，移出后放开取消。余额不足的购买、购买合成、刷新按钮只下沉半程并短暂提亮缺额；已售出商品保持静止。成功购买立即结算、更新余额并发出短促金币声。连续刷新无需等待回弹，武器二合一即时完成。普通按压使用短音，静音沿用原有 M 键。

升级数字键按下时压住对应选项，松开同一个键才选择，失焦取消。战斗时生命实值即时更新，旧血量短暂停留后退去；诱饵就绪时铃铛摆一次，围攻从零进入时提亮一次。

楼层净化与最终胜利分别默认演出 0.6 秒和 1.2 秒。沿用场景里的声圈，从守关者位置扩散淡出，暂停的战场上逐渐显出记录。演出期间首次点击或按确认键只展开结果，结束后按钮或再次确认执行下潜 / 重开。失败立即显示结果。

## 文件与配置

- `HudButton.cs`、`GameHud.Feedback.cs` 处理按钮行程、事件动效与结算输入。`GameHud.cs`、`GameHud.Art.cs`、`GameHud.Screens.cs`、`GameHud.Shop.cs` 连接现有页面。
- `RunController.cs` 将结算快捷键交给 HUD。`NoiseSystem.cs` 使用现有合成短音方式播放界面声音，独立于敌人听觉。
- 在 GameConfig 的 Interface feedback 分组调整按钮下沉量、残血条时长和两种结算演出时长。默认下沉 2 个参考画布单位，残影约 0.4 秒。无需更新贴图或场景绑定。

## 验证与已知限制

独立 Unity 副本通过 8 项 PlayMode 用例，涵盖按压与取消、缺额和售罄、重复刷新、升级确认、伤害残影、结算跳过、商店交易与调试设置。`HudFeedbackTests.cs` 包含本轮的 3 项回归测试。修整结算开始时的旧提示后，复验跳过逻辑，并从实际第三层守关者的死亡事件录制[最终胜利动图](Images/界面操作反馈/最终胜利.gif)。

键盘验证覆盖输入处理逻辑；按压音和金币音的响度尚待真人试听。GIF 无声。
